1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
SecureSBOM (PRJ_56) is a Software Supply Chain Security Platform, OWASP
CycloneDX SBOM Generator, Dependency Vulnerability Scanner, and AI-Assisted
Security Reference System built for Python (PyPI) projects.

It ingests dependency manifests, resolves direct and transitive dependency
graphs without executing untrusted package code, generates schema-validated
CycloneDX v1.4/v1.5 JSON SBOMs, correlates multi-source vulnerability advisories
(OSV, NVD, GitHub Advisory Database, CISA KEV, FIRST EPSS), auto-enriches
UNKNOWN-severity vulnerabilities, and provides OSV-verified upgrade paths plus
an AI-assisted Latest Dependency Reference Check.

3. HOW THE SYSTEM WORKS (END-TO-END WORKFLOW)
--------------------------------------------------------------------------------
Step 1 - Manifest Ingestion:
  User uploads or pastes requirements.txt, pyproject.toml, poetry.lock,
  Pipfile.lock, or CycloneDX JSON in the New Scan view. The parser validates
  file size, rejects untrusted URLs, evaluates environment markers, and
  normalizes package names per PEP 503.

Step 2 - Transitive Dependency Resolution:
  The resolver queries PyPI release metadata concurrently (no code execution)
  to resolve direct and transitive packages up to depth 3, building Package
  URLs (PURLs) and detecting dependency cycles.

Step 3 - CycloneDX SBOM Generation:
  cyclonedx-python-lib generates an OWASP CycloneDX v1.4/v1.5 JSON document
  containing all resolved components, PURLs, and dependency edges, saved to
  output/bom.json and downloadable per scan.

Step 4 - Vulnerability Scanning & Canonical Correlation:
  The scanner queries Google OSV concurrently, enriches CVEs with NIST NVD
  CVSS v3.1 scores, CISA KEV exploitation status, and FIRST EPSS scores, and
  clusters aliases (CVE/GHSA/PYSEC) using connected-component graph grouping
  to eliminate duplicate counting. Any UNKNOWN findings trigger automatic
  lookups against GitHub Security Advisories and OSV full records.

Step 5 - Persistence & Reporting:
  The scan, components, and canonical vulnerabilities are persisted in a single
  atomic database transaction. Users can inspect results, view the Live
  Open-Source Reference Feed, run Safer Alternatives + AI Latest Dependency
  Check, and export PDF, CSV, or JSON compliance reports.

4. HOW AI IS USED IN SECURESBOM
--------------------------------------------------------------------------------
SecureSBOM follows a strict "AI-Assisted, Never Authoritative" architecture:

1. Strict Three-Category Separation:
   - Category A (Confirmed Vulnerabilities): Deterministic OSV/NVD/KEV/EPSS
     matches only. AI never modifies or inflates Category A counts.
   - Category B (Emerging Vulnerability Intelligence): Evidence-grounded RAG
     findings from public advisories, clearly labeled as non-confirmed.
   - Category C (Potential Weaknesses): Static AST pattern checks and AI
     hypotheses requiring human verification.

2. AI Latest Dependency Reference Check (in Safer Alternatives):
   - Checks scanned dependencies against live PyPI latest stable versions and
     OSV status, generating AI-assisted upgrade reference pins and notes for
     client review without modifying project files.

3. Evidence-Driven RAG Pipeline:
   - Retrieves relevant intelligence via SQLite FTS5 + TF-IDF cosine hybrid
     search, verifies PEP 440 version applicability deterministically, strips
     indirect prompt-injection directives from untrusted advisories, validates
     citations, and abstains when evidence is insufficient.

4. Configurable Providers (Zero Mandatory Paid Keys):
   - Supports No-AI / deterministic mode (default), Local Ollama / llama.cpp,
     OpenAI-compatible endpoints, Google Gemini, and an explicit mock provider.
